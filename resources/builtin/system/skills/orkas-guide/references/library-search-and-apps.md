# Library, search, and saved apps

## Reuse knowledge with Library

Use **Library** for sources and deliverables needed across tasks. The global Library holds general material; a Project Library keeps that Project's sources together. Add a supported file, give it a recognizable name, and wait for processing. Select the relevant source in a task and explain how to use it; adding a source does not make every task use it automatically. One-task inputs can remain attachments. Memory holds concise durable facts rather than source documents.

## Find work across Orkas

Open sidebar **Search** (Cmd/Ctrl+K), enter a distinctive title, phrase, file name or Project name, and press **Enter**. Filter by **Tasks**, **Agents**, **Skills**, **Library**, **Automation**, **To-do** or **Connectors**. Automation and To-do include disabled or completed items; connector results include catalog and custom connections. Open a result to reveal its entry.

Outside a Project, Library search covers processed sources across Projects; inside one, it covers that Project plus the global Library. If something is missing, clear filters, check its Project/device and active account, allow processing or commercial cloud sync to finish, then check **Account settings > Data > Recycle Bin**.

## Create, save, and revise an app

Open **Apps > Create**, describe the tool or choose a starter, then select **Create**. Generation starts in a new task; review the result and choose **Save as app**. A failed start keeps the description for retry. Configure a model if prompted. Static reports can remain files or Library deliverables.

**Apps** groups saved apps under **Custom** and bundled apps under **Platform**. In the commercial edition, published custom apps appear first. Open a saved app directly, or click an app shortcut in a reply when offered. Platform **Edit a copy** starts a task for an independent custom version; platform originals update with Orkas.

- In a task result, **Save as app** saves the first version; **Update original app** keeps its identity and compatible data; **Save new app** creates an independent copy. Later saves from that result target the copy. **Apps > Edit** starts a revision task. With these manual save actions, a deleted original is saved as a new app.
- In the source task, Commander can also save an app result or an app folder in the workspace. Its updates check the saved destination and version: a changed or deleted destination stops the update. Ask explicitly for a new copy if that is the intended recovery. Incompatible data updates stop without clearing records; use the result's save action to review export and recovery.
- Saving and updating an app do not publish or update a public website. Export important data before changing copies or making incompatible revisions.

## Use Content workspace

Open **Apps > Platform > Content workspace**. Choose **Images**, **Video** or **Audio**, describe the work and optionally add files, then select **Start creating**. ImageStudio, VideoStudio or VoiceStudio runs in the background. There is no operation selector; describe generation, editing, transcription or cleanup in the request.

- **Service / model** or **Speech service** selects a configured service for that request without reordering Settings. The first available service is selected initially. **Refresh** reloads choices; **Configure models** opens **Settings > Models** on the matching Image, Video or Speech tab, including when no service is available. Returning preserves the draft and refreshes choices. Replace an unavailable selection before creating.
- Proportions, target duration and delivery format are optional guidance. **No preference** or an empty duration leaves the choice to the task. A usable result in another proportion or format is kept without automatic regeneration. TXT/SRT/JSON requests hide irrelevant media settings.
- Paste screenshots or copied files, drag them onto the input, or choose **+ > Local files** or **+ > Material library**. Up to 19 files are allowed within the shown format/size limits; valid imports remain if another file fails. Ordinary text paste stays text.
- New requests deliver without intermediate questions or approvals; **Start creating** authorizes the selected configured service, which can incur provider charges. Missing required input, permissions or service access appears as a failed record. App runs stay outside the normal conversation list. Closing the app does not stop work already started; reopen it to check results.
- Expand **History** records to preview inputs/results or read a failure explanation. The record menu offers **Edit** to restore the original input as a new draft, **Refresh** to retry saving results without another generation, **Continue** when a task is waiting for an answer, **Stop**, and confirmed **Delete**. **Show more** loads older records.
- Result menus offer **Use as material**, **Save as material**, **Open** and **Show in folder**. Use appends the file to the current input; Save keeps it in Material library. Open and Show in folder need the saved file on this device. Image, video and audio results include the saved file; TXT/SRT/JSON tasks can deliver text.
- Each media tab keeps its draft. **Reset** confirms before clearing text/files and restoring defaults; history and running work remain. Removing an attachment or record keeps original files. The open-source build keeps drafts, history and saved results locally; account cloud sync applies only in the commercial edition. Adding a local source file does not sync its whole folder.

## Reuse materials

**Material library** inside a workspace is separate from the global Library. It keeps text, images, audio, video and combinations. **Add text** saves authored request text; **Add media** imports multiple files. Uploaded sources enter this library automatically; generated results enter only through **Save as material**.

Select material, choose the destination media type, then **Use** to fill its input without starting work. Authored text replaces the request; documents remain file attachments. Files append without duplicates, preserving settings and, for file-only selections, existing request text.

In **All**, select at least two items and choose **Save as combination**. Existing combinations can be included; shared files appear once. A saved combination keeps its text independently of later text-item edits. Edit text or combinations to change their name/text. Select items and confirm **Remove** to delete library entries only; history, original files, unselected combinations and a removed combination's component files remain. Restore missing files from their original source or a local backup; cloud-sync recovery is commercial-edition only.

## Use Commerce workspace

Open **Apps > Platform > Commerce workspace** for **Stores** and **Media creation**. In Stores, **Connect store** opens Connectors; **Back · Commerce workspace** returns with the draft intact. Store identities come from authorized connectors. **Refresh** retries a lookup; retained reports remain visible with a warning if refresh fails.

Sales currently covers Shopify only: at most 1,000 orders from the last 30 days. Sales totals account for returns and exclude tax, shipping, cancelled and test orders. Incomplete reports retain previous data; unavailable services are not zero sales, and currencies stay separate. The open-source build keeps store records and reports locally; account cloud sync applies only in the commercial edition. Manage lost authorization in Connectors.

In **Media creation**, choose **Copy**, **Images**, **Video** or **Material library**. Enter **Core content** and select **Start creating** for product copy through ContentWriter; no product record is required. Images/video, history and material actions follow the same workflow as Content workspace, with separate data. Restore an unavailable Agent in AI Team and refresh.

Product management, import, store drafts and publication are currently unavailable; existing product data is retained. Where existing product context is available, selecting it supplies a copy of its facts without clearing the request/settings. **+ > Product references** adds reference files; History can filter by product. Library **Use for product** adds selected images/videos to an associated product without publishing.

## Publish an app (commercial edition only)

In **Apps**, use the app menu's **Publish**, or its hover button when shown. Unpublished custom apps with a copy on this device offer **Share** on the card and in its menu, including after unpublishing. Published apps hide both Share entries. The Apps page and publishing dialog show your publication allowance. Apps that need desktop-only features cannot be published. **Modify app for web publishing** opens an editing task with a prepared request; review and send the request yourself. Membership and available cloud storage are required. Visitors open the published link without signing in.

Local edits need an explicit **Update publication** and the source on this device. Published menus offer **Update publication** and **Unpublish**. **Publication details** shows the link, PV, status, storage and online records; query, edit, delete or export records there. **Clear all data** or **Clear this table** removes online records while keeping the app usable.

Published files and online data share account cloud storage with sync and collaboration. A full account blocks growth, not reads or deletion; reclaimed storage may lag record deletion. Local and online data are independent: first publication starts empty, updates preserve compatible online records, and personal sync never transfers online records. Previews use temporary data.

Platform suspension closes public access; data is retained, and author export/cleanup remains available. **Unpublish** and expiration cleanup permanently delete online records, files and PV while keeping the saved app and its local data. **Delete** is hidden until unpublishing completes, including for suspended apps. Suspended apps count toward the limit. Follow the displayed seven-day deadline after expiration or an over-quota downgrade.

## Use Orkas capabilities inside an app

Local apps built for Orkas can use configured models, private storage, selected files, text exports, global Library, connectors and Agent tasks. Availability depends on the app and configuration; older apps do not gain capabilities automatically. Request a revision in its source task. A standalone HTML export does not carry Orkas capabilities into an ordinary browser.

- Selecting a file gives the app a read-only copy; it cannot edit the original. Export text to a new filename; existing files are protected.
- Model generation can incur charges and does not ask for separate app consent. It uses the app's submitted text without automatically including conversation, Agent or Project context.
- Library access needs no separate app consent. Connector actions follow existing tool permissions and may change external data or incur fees. **Allow for this use** covers the approved connector account and sensitive action type while this app stays open. Closing and reopening requires a new approval; other apps do not share it. **Trusted** runs available actions without confirmation. Prohibited actions remain unavailable.
- Apps with Agent-task support show their own runs and files. Tasks needing an answer show questions/approvals inside the app through **Continue**; **Stop task** requests cancellation. Each app can access only its own runs. Check uncertain outcomes before repeating a generation or store action.
- Each app has independent private data and files, kept locally in the open-source build. Cloud storage syncs (commercial edition only) when the same account enables sync on each device. Saved does not mean uploaded. Older local data is not moved automatically. Reopening restores the same app's data; a new copy starts independently. Resolve competing edits in **Account settings > Data**, then close and reopen.
- Apps can follow Orkas's language; reopen after changing it. A fixed-language app needs a revision. Apps may send data to external services directly without a connector approval dialog. Those services may require their own sign-in or permissions.

After an account, source or model-setting change, close and reopen the app. If a model is unavailable, configure one first. Denied permissions or cancelled pickers can be retried when ready; export failures may need a new filename on a supported filesystem. Cancellation does not undo external actions or prove that no model charge occurred; check before retrying.
